# 横川AI：Webアプリが動かない場合の上演継続キット

このフォルダだけを、事前に音響PCと映像PC／USBメモリへコピーしてください。Webアプリ、Node、インターネット、音声合成エンジンは不要です。音響と映像は別の担当者・別の再生機で操作します。

## 音響

`audio`の20 WAVは、Google Docs台本の`AI：`に続くCue表記と同じ名前です。順番は`Cue一覧.csv`で確認してください。ファイル名の辞書順は上演順ではありません（P-019がP-V02の前に入ります）。台本原本には編集・コメントを加えていません。

- 48kHz／16-bit PCM／ステレオ。既存の承認済みWAVを再利用。起動音・HACKノイズ・ERROR警告音・復旧SEを、現在のCue内タイミング・音量比で合成済みです。HACK発話のフィルター／短いdelayも既存の処理を使っています。
- Cue内の冒頭待ち・文間・SE終了待ちは含みます。実機のHDMI latency、次のCueまでの2秒、役者や観客を待つ時間は追加していません。
- 予備WAVには全Cue共通で−3dBの余裕を設けています。個別の音量正規化はしていません。PAでの共通再生レベルは事前に調整してください。
- **単発再生／連続再生OFF／自動次Cue OFF**で登録してください。台本の合図で該当するWAVを1本だけ再生し、次は役者・観客の合図を待ちます。
- P-V04／P-V05は音なしCueです。1秒の完全無音WAVを用意していますが、音響の再生操作は不要です。映像担当だけが切り替えます。
- P-V07は4.6秒後に復旧SEを再生します。現在配置された`production-recovery.wav`をそのまま使用しています。
- P-012は解錠開始4.519秒後から5.0秒、P-V07は復旧開始直後から3.8秒のゲージ音を含みます。ゲージ音素材のみ、ユーザーが試聴して採用した元音源比＋12dB版。末尾40msのフェードと共通−3dBの余裕を反映済みです。
- P-020のファイル名は台本の旧Cue名「全館の扉・解錠確認」。音声の内容は現在承認済みの「館内すべての安全を確認しました」です。古いセリフへ戻していません。

## 映像・謎提示

`visual`に上演順の番号付きPNGが20枚あります。現在のDisplayから取得した各Cue終了時点の**静止画**です。映像の動きや途中の進捗を再現するものではありません。字幕は画像を邪魔しないよう全て除いています。1枚を表示したまま、役者・観客の合図で次を手動表示してください。音のない画像なので、WAVとの二重音声は起きません。

`puzzles`の3 PNGは現在の本番原本そのままです。謎提示を最優先する場合は、この3枚を画像ビューアーの「全体表示／縦横比維持」で開いてください。「塗りつぶし／ズーム／切り抜き」は使いません。

| 合図 | 必須の謎原本 |

| P-V02 第一の謎 | production-puzzle-01.png |
| P-011 最終問題 | production-puzzle-06.png |

投影PCまで故障した場合に備え、3謎の原本を読みやすい大きさで事前印刷して複数部用意します。文字・図の四辺を切らず、客席距離で確認してください。俳優／案内担当が掲示し、観客の回答を待ちます。進捗・ERROR・復旧の動きは静止画と音声・芝居で補い、存在しないSEや別の謎は追加しません。

## 本番中の切替

1. 舞台進行担当が「横川AIを予備運用へ」と音響・映像へ宣言し、現在／次のCue IDを揃えます。
2. 旧Webアプリの音声をSTOPし、必要なら旧PC出力をミュートします。**旧系と予備系を同時に鳴らさない**ことを最優先します。
3. まだ発話していないCueなら、そのWAVの先頭から再生。途中で切れた場合は勝手に冒頭から重ねず、進行担当が「該当Cueを再演する／次のCueへ進む」を決め、役者と合図を合わせます。1本のWAV内の途中再開は事前に取り決めた場合だけ行います。
4. 映像担当は対応PNGへ移動。謎を解く間は謎PNGを保持し、音声が終わっても勝手に次へ進みません。
5. 復旧したWebアプリはSTOP状態で待機させます。緊急Cue移動で「次に開始するCue」を指定し、区切りで進行担当が戻すと宣言してから明示NEXTします。途中から二重再生しません。

事前に「音響だけ故障／映像だけ故障／Webアプリ全停止／投影PCも故障」の4ケースを、実際の音響再生ソフトと予備PCで一度通してください。本キットの検証はファイルの内容・タイミング・表示であり、会場PA・HDMI・客席聴感の合格を保証するものではありません。

`manifest.json`には全WAVのSHA256、元WAV、各SE／発話の開始位置とgain、台本modified time、Cueの合図が記録されています。
